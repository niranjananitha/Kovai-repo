# Build Log

A short factual entry for each thing that failed during the build.

| # | What failed | Cause | Fix |
| --- | --- | --- | --- |
| 1 | The first scaffold command (a large shell command writing several files) stopped with `unexpected EOF while looking for matching '`'`. Nothing was written. | A quoting problem in the combined shell command. | Wrote each file separately instead of one big shell command. |
| 2 | `pytest`: `test_unexpected_error_returns_json_without_stack_trace` failed with `RuntimeError: Working outside of application context`. | The test replaced `Task.query` with `monkeypatch`, which itself reads `Task.query` outside an app context. | Replaced the whole `Task` name inside `app.tasks` with a small object whose `query` raises an error. All 39 tests then passed. |
| 3 | A command to stop the local Flask test server (`taskkill` of all `python.exe` processes) was denied by the tool's safety check. | The command was broader than needed and was blocked. | Not retried. The server must be stopped by hand if it is still running (see the hand-over notes). |
| 4 | First Render deploy failed. The build passed, but gunicorn exited at start with `sqlalchemy.exc.ArgumentError: Could not parse SQLAlchemy URL from given URL string`. | The `DATABASE_URL` value entered in Render was not a valid database URL (it was not the `postgresql://...` connection string). | Replaced the value in Render's Environment settings with the real Neon connection string and redeployed; the service then went live. |
| 5 | While checking the new interface, `POST /api/auth/register` returned 405 "method not allowed". | An older backend process (started before the new routes existed) was still listening on port 5000 and answering. Stopping it was blocked by the tool's safety check. | Ran the checking backend on port 5055 and loaded the built frontend from it. The old process still needs stopping by hand. |
| 6 | The Planned and In Progress symbols showed in the text colour, not slate and blue. | Tailwind v4 leaves out theme colours that no utility class uses, and the symbols used them only through inline `var(--color-...)`. | Changed `@theme` to `@theme static` in `index.css`. |
| 7 | Opening New task did not put the cursor in the title box. | The native `<dialog>` focuses its first control (the Close button) when opened. | Focus the title field right after `showModal()`. |
| 8 | A touch-target audit at 360 px wide found the Board/List toggle (40x36) and the drag grips (32 wide) below 44 px, and the New task button wrapped onto a second row. | Sizes were set for desktop. | Raised the sizes to 44 px, hid the toggle on phones (the menu has Board and List) and made New task icon-only on phones. |
| 9 | Muted text on the board columns measured 4.34:1 contrast, under the 4.5:1 target. | `#5E6A7D` is slightly too light on the grey column colour. | Darkened the muted colour to `#566274` (4.91:1). |
| 10 | While checking, six wrong guesses for one email locked that account out of password login for 15 minutes. | This is the login rate limit working as designed (per email, in memory). | Restarted the checking backend to clear the counter. Documented the denial-of-service side effect in the README and ASSUMPTIONS. |
| 11 | Checking the live site: the session cookie had `Secure=false` although production mode should make it Secure (it was HttpOnly, SameSite=Lax and 7 days as expected). | The code is correct, so most likely `FLASK_ENV` on Render was not exactly `production` (for example a capital letter or a space). The exact value in the Render dashboard was not inspected. | The check now ignores case, spaces and quotes, and new tests cover the production settings (refuses to start without `SECRET_KEY`, Secure cookie). After redeploying, the live login response set `Secure; HttpOnly; SameSite=Lax` with a 7-day expiry, so the fix is confirmed. |
